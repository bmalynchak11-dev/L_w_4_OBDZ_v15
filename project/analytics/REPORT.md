## Запити
- q01: Аналізує календарні когорти клієнтів за датою першого візиту за допомогою CTE.
- q02: Отримує хронологічний перелік відвідувань обраного учасника за визначений період через JOIN.
- q03: Ранжує візити кожного клієнта за сумою оплати за допомогою віконної функції RANK.
- q04: Розраховує виручку та загальну кількість візитів за назвами тренувань через JOIN.
- q05: Вибирає активні заброньовані візити на майбутні дати серед усього масиву.
- q06: Зводить загальну кількість та середній чек подій за їхніми статусами.

## План до і після

### q02
```text
Nested Loop  (cost=0.00..2848.50 rows=28 width=44)
  ->  Seq Scan on visit v  (cost=0.00..2845.00 rows=28 width=28)
        Filter: ((visited_at >= '2024-06-01 00:00:00'::timestamp) AND (member_id = 42))
  ->  Index Scan using workout_pkey on workout w  (cost=0.14..0.18 rows=1 width=24)
        Index Cond: (id = v.workout_id)
```

```text
Nested Loop  (cost=0.43..12.25 rows=28 width=44)
  ->  Index Scan using visit_member_visited_idx on visit v  (cost=0.29..8.55 rows=28 width=28)
        Index Cond: ((member_id = 42) AND (visited_at >= '2024-06-01 00:00:00'::timestamp))
  ->  Index Scan using workout_pkey on workout w  (cost=0.14..0.18 rows=1 width=24)
        Index Cond: (id = v.workout_id)
```
Тип вузла читання таблиці visit змінився з Seq Scan на Index Scan. Оцінка вартості знизилася з 2848.50 до 12.25, а очікувана кількість рядків rows=28 точно відповідає вибірці без сортування в пам'яті.

### q05
```text
Seq Scan on visit  (cost=0.00..2845.00 rows=480 width=20)
  Filter: ((visited_at >= '2024-09-01 00:00:00'::timestamp) AND (state = 'booked'::text))
```

```text
Bitmap Heap Scan on visit  (cost=4.65..85.20 rows=480 width=20)
  Recheck Cond: ((visited_at >= '2024-09-01 00:00:00'::timestamp) AND (state = 'booked'::text))
  ->  Bitmap Index Scan on visit_booked_partial_idx  (cost=0.00..4.53 rows=480 width=0)
        Index Cond: (visited_at >= '2024-09-01 00:00:00'::timestamp)
```
Послідовне читання Seq Scan замінено на Bitmap Heap Scan за допомогою часткового індексу. Вартість знизилася з 2845.00 до 85.20, оцінка рядків rows=480 збігається з фактичною кількістю відкритих записів.

## Висновок
Оптимізація індексами є критично важливою виключно для високоселективних запитів q02 та q05, оскільки вони фільтрують менше одного відсотка всіх рядків великої таблиці за конкретним ідентифікатором користувача або рідкісним статусом бронювання. Складений і частковий індекси дозволяють оптимізатору миттєво знаходити цільові сторінки без перегляду всієї таблиці обсягом понад сто тисяч записів. Натомість для аналітичних агрегацій q01, q04 та q06, які сканують більшу частину даних або групують усі записи, послідовне читання Seq Scan є значно ефективнішим, а додаткові індекси лише створили б зайве навантаження на дискову підсистему та суттєво уповільнили б операції додавання й модифікації рядків.
